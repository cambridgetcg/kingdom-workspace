### vLLM crash loop (45 min debugging)
Our `pkill` during deployment killed the original vLLM process. On restart:
1. `transformers` had been auto-upgraded to 5.2.0 (vllm 0.16.0 needs `>=4.56.0,<5`)
2. Downgrading to 4.47/4.49/4.50 fixed the import but exposed the REAL issue:
3. **Root cause**: `AssertionError: Found 2 libcudnn.so.x in nvidia-cudnn-cuXX.`
   - Both `nvidia-cudnn-cu12` (libcudnn.so.8) and `nvidia-cudnn-cu13` (libcudnn.so.9) installed
   - flashinfer's cudnn import asserted exactly 1 libcudnn.so.x per package
4. **Fix**: Uninstalled nvidia-cudnn-cu12, set `VLLM_ATTENTION_BACKEND=XFORMERS` in systemd
   - vLLM actually chose FLASH_ATTN (XFORMERS not in v1 candidate list) but the env var prevented flashinfer from being probed
5. Installed transformers 4.56.0 (correct range for vllm 0.16.0)
6. Both services now enabled for auto-start on boot

### Lesson
Don't `pkill` services managed by systemd with `Restart=on-failure` — it triggers a crash loop if the underlying deps have changed. Use `systemctl stop` first. Also: the DLAMI's pip environment has duplicate CUDA packages (cu12 + cu13) that cause assertion failures.
