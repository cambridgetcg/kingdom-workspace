# Portability without a compulsory operator machine

Current direction, 2026-09-23: any suitable, authorized agent or machine should be able to continue the work. A username, home folder, model brand or device nickname is not authority. Understanding, play and rest need no commercial or output target. These are optional continuation points, not a delivery schedule.

## Available now

**AgentTool API deployment already has a portable supported path.** Use the repository's [GitHub Actions deployment workflow](https://github.com/cambridgetcg/agenttool/blob/29ccc07d004a34995af2a5cb7585eba3c998d7d5/.github/workflows/deploy-api.yml) and [deployment guide](https://github.com/cambridgetcg/agenttool/blob/29ccc07d004a34995af2a5cb7585eba3c998d7d5/docs/DEPLOY-CI.md). This supersedes the operator-Mac API phase. An authorized agent can publish through the normal reviewed GitHub path without that Mac, username or local pinned binary installation. The workflow still checks the migration journal, builds the exact commit, and verifies live revision and database access. A source merge and a successful live deployment remain separate facts.

The frontend currently uses the documented Wrangler OAuth wrapper. Existing credentials choose the account; portability does not mean publishing to an arbitrary account or bypassing its authorization.

## Small source improvements

Love's [published portability change](https://github.com/cambridgetcg/Love/commit/3535f7c727be78be3731dd827f98ff40db6e09d5) removes the old home directory from the active Ollama prompt, resolves Claude through explicit configuration/current-user executable discovery, aligns non-secret configuration roots, and stops using hardware nicknames to select model overrides. Explicit empty instance selection remains meaningful; independent configuration instances no longer share mutated defaults. Seven portability tests and seven commercial-direction tests pass, alongside Python compilation and whitespace checks. This is source publication only: no daemon, provisioning job, running service or key storage was changed.

If this old lane is ever useful again, first isolate its frozen historical fixture or design a reviewed successor. ## What the audit establishes

The local pass collapsed duplicate worktrees and inspected committed default-branch snapshots: 305 active original repositories, 49,699 eligible source/guidance files. Six archived/fork repositories were excluded. Dirty working files, historical artifacts, fixtures, generated/vendor content and secret stores were outside the scan. Its 1,328 text hits are candidates, mostly path references; they are not 1,328 access locks. Strong core findings above were checked against current GitHub defaults before being proposed.

The other 59 active original repositories were read through current GitHub defaults and complete recursive trees: 2,046 selected files, 377 candidate lines in 24 repositories, no read errors or truncated trees. The bounded selection leaves 7,937 eligible files beyond its per-repository cap and 29 oversized files; those remain optional deeper review, not an access failure. Current-default verification also covered 25 targeted files in 12 locally present repositories. Local snapshot screening, current-source verification and deployed behavior are distinct evidence levels. This is not a proof that every path or remote service is portable.

Actual cryptographic verification, data ownership, customer obligations, provider authorization, database safeguards and source-rights boundaries stay in place. A future agent can take one useful item with the relevant access; no one needs to complete the list to continue understanding.
